## Inventário e decisão de autenticação

| Área | Estado anterior | Fecho A4.2 |
|---|---|---|
| `users` | EXISTING | `login`, `password_hash`, lifecycle, MFA gate e public ID são a fonte canónica |
| `auth_sessions` | EXISTING | Reutilizado para digest, user, expiry, revogação e versão |
| Middleware bearer | PARTIAL | Distingue unknown, expired e revoked; revalida user e grants |
| Login/logout/me HTTP | MISSING | Implementados em `/api/v1/auth` |
| Rate limiting | PARTIAL | Limiter de login explícito, 5/minuto/IP, sem Redis obrigatório |
| Frontend auth | PARTIAL | Login/logout reais, sessionStorage, guard, 401 e menu por permissões |
| Refresh | MISSING | Formalmente `NOT_APPLICABLE` no modelo V1 |

Decisão: **MEPA Local Auth V1**, formalizada em ADR-0016 e `docs/api/authentication_v1.json`. O identificador é `users.login`; o segredo é `users.password_hash`, verificado pelo Laravel Hasher. Não foi criado segundo sistema de identidade ou sessão.

## Contrato

- `POST /api/v1/auth/login`: `201`, bearer aleatório de 32 bytes, expiry e projecção pública mínima.
- `GET /api/v1/auth/me`: user público e expiry da sessão autenticada.
- `POST /api/v1/auth/logout`: `204`, revogação do token conhecido e repetição determinística.
- Wrong password e conta inexistente devolvem o mesmo `401 INVALID_CREDENTIALS` e a mesma mensagem.
- `UNAUTHENTICATED`, `SESSION_EXPIRED` e `SESSION_REVOKED` devolvem `401`; throttle devolve `429 RATE_LIMITED`.
- O digest persistido é SHA-256 binário; raw bearer/password não é registado.
- A sessão expira fixamente após 480 minutos por omissão. Não há sliding expiry.

Refresh é `NOT_APPLICABLE`: a tabela tem um único bearer, sem credencial renovável separada, família de rotação ou limite absoluto de renovação. Expiração requer novo login; sessão revogada nunca é ressuscitada.

## Frontend

A tela pt-AO usa labels visíveis, validação, estado de loading, erro genérico, feedback de rate limit, submissão por teclado e alternância de visibilidade da palavra-passe. O bearer fica apenas em `sessionStorage`, nunca em URL/query string. Logout chama a API e limpa sempre o estado local no `finally`. Um `401` limpa a sessão; os guards voltam a `/entrar`, e `safeRedirect` aceita apenas caminhos internos. O menu deriva das permissões efectivas de `/academy/context`.
